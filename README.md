1. Une modification dans le répertoire de travail est enregistrée dans le fichier mais n’est pas encore prête à être commitée. Une modification préparée a été ajoutée à la zone de préparation (staging area) avec git add et sera incluse dans le prochain commit. exercice.md
2. À l’étape 3, git reset --soft conserve les modifications dans la zone de préparation, donc on peut refaire directement un commit. À l’étape 4, git reset --mixed conserve les modifications dans les fichiers mais les retire de la zone de préparation. Il faut donc refaire git add avant de pouvoir les commiter. exercice.md
3. Le paramètre temporaire a été supprimé lors de l’annulation avec reset --hard. Cette opération supprime également les modifications non enregistrées des fichiers suivis. exercice.md
4. La modification était présente uniquement dans le dépôt local. Elle n’était pas encore visible sur GitHub parce qu’aucun nouveau git push ne devait être effectué avant l’étape 7. exercice.md
5. Une annulation destructive comme git reset --hard peut provoquer la perte définitive de modifications non sauvegardées. Dans un environnement d’administration système, cela peut faire perdre des changements importants de scripts ou de configuration et potentiellement entraîner des erreurs de fonctionnement. exercice.md
